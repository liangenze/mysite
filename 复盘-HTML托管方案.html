复盘：HTML托管方案探索

2026年6月 · 恩泽 × 小赫（Hermes Agent）

📋 背景

需要将 AI 生成的 HTML 文件（架构图、原型等）通过链接分享给同事，要求：

  • 手机浏览器 / 飞书内直接打开，能正常显示
  • 无需下载文件，点击链接即看
  • 免费、简单、稳定

一、方案一：腾讯云 COS

✅ 步骤

Step 1

创建存储桶 mysite-1439242851，区域 ap-beijing

Step 2

安装 cos-python-sdk-v5，编写上传脚本 ~/.hermes/scripts/cos-upload.py

Step 3

设置存储桶权限为「公有读」

Step 4

上传文件，自动设置 Content-Type: text/html + Content-Disposition: inline

Step 5

开启「静态网站」功能，配置默认首页 index.html

❌ 结果

电脑浏览器 正常显示 ✅

手机飞书内置浏览器 强制下载 ❌

手机夸克浏览器 强制下载 ❌

🔍 原因分析

  • COS 的对象存储 URL 本质是「文件下载链接」，即使设置了 inline 头
  • 飞书内置浏览器和部分手机浏览器会覆盖 Content-Disposition，强制触发下载
  • COS 静态网站模式（cos-website 域名）解决了电脑端，但手机端仍有问题
  • 根本原因：COS 不是真正的 Web 托管服务，只是对象存储

📌 经验教训

  • 设置 Content-Type: text/html 和 Content-Disposition: inline 不够
  • COS 静态网站功能在手机端不可靠
  • 对象存储 ≠ 静态网站托管，别被「静态网站」功能名误导

二、方案二：GitHub Pages

✅ 步骤

Step 1

生成 GitHub Classic Token（细粒度 token 权限不足，不支持创建仓库和推送）

Step 2

手动创建公开仓库 liangenze/mysite

Step 3

克隆仓库，放入 index.html，推送

Step 4

通过 GitHub API 开启 Pages（source: master 分支）

Step 5

等待部署生效（约 1-2 分钟）

✅ 结果

电脑浏览器 正常 ✅

手机浏览器 正常 ✅

飞书内打开 正常 ✅

⚠️ 注意事项

  • 部署后需要 1-2 分钟生效，首次可能返回 404
  • 国内网络访问 GitHub Pages 可能不稳定，建议多试几次
  • 文件名用英文（如 arch.html），中文路径虽然能用但 URL 不好看
  • GitHub Pages 是真正的静态 Web 托管，浏览器会正确处理 MIME 类型

四、踩过的坑

  1. COS Content-Disposition 设置无效
    即使设置了 inline，手机浏览器仍会下载。对象存储的响应头不能覆盖浏览器的默认行为。
  2. GitHub 细粒度 Token 权限不足
    Fine-grained token 无法创建仓库和推送代码，需要 Classic Token + repo 权限。
  3. GitHub Pages 部署延迟
    开启 Pages 后不会立即生效，需要等待 1-2 分钟。不要一看到 404 就以为配置错了。
  4. master vs main 分支
    手动创建的仓库默认分支是 master，GitHub Pages 需要对应配置。推送时也要用 master。
  5. 中文文件名
    能用但 URL 会变成百分号编码（%E5%A4%9A...），不美观也不好分享。建议用英文。

五、最终方案

GitHub Pages + Git 工作流

# 上传新文件
cp new-file.html /tmp/mysite/
cd /tmp/mysite
git add -A && git commit -m "add: xxx"
python3 /tmp/push_git.py

# 访问链接
https://liangenze.github.io/mysite/arch.html

后续更新页面，推送到 master 分支即可，GitHub Pages 自动部署。
